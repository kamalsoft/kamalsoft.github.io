# SBOM gate

SBOM gate: a complete software bill of materials produced for each release. Read the code or data before you judge it, and do not change files unless the user asks for a fix.

## Protocol

1. **Confirm the SBOM is generated by the pipeline for each release.**
2. **Set the rule.** A release without an SBOM does not pass.
3. **Check completeness.** The SBOM must include transitive packages.
4. **Check storage.** The SBOM is kept with the release record.
5. **Report.** The release, the SBOM status, its component count and any gap.

## Post-production

- **Missing SBOMs** cannot answer 'are we affected' quickly. Require one per release.
- **Hand-made SBOMs** drift from the shipped code. Generate them in the pipeline.

## Not checked

Runtime behaviour under load, and anything outside the files, data or export the user gave.
