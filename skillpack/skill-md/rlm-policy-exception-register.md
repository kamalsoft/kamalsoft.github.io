# Policy exception register

Policy exception register: every departure from a policy recorded with its reason, owner and expiry. Read the code or data before you judge it, and do not change files unless the user asks for a fix.

## Protocol

1. **List the exceptions.** Each departure from policy, with the policy it breaks.
2. **Check the reason.** Each needs a stated reason.
3. **Check the owner and expiry.** Each needs an owner and an end date.
4. **Check the approval.** Each needs an approver above the team.
5. **Report.** The register, the expired exceptions and those for renewal.

## Post-production

- **Unrecorded exceptions** are found in audit as violations. Record them when made.
- **Expired exceptions** that continue are violations. Review each month.

## Not checked

Runtime behaviour under load, and anything outside the files, data or export the user gave.
