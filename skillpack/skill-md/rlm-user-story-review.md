# User story review

User story review: stories with a user, a need, a benefit and clear boundaries. Read the code or data before you judge it, and do not change files unless the user asks for a fix.

## Protocol

1. **Check the form.** Each story names a user, a need and a benefit.
2. **Check size.** Flag stories too big to finish in one iteration.
3. **Check boundaries.** Flag stories with no stated exclusions.
4. **Check dependencies.** Flag stories blocked by work not yet done.
5. **Report.** Each story with its gaps and the rewrite.

## Post-production

- **Oversized stories** slip and hide risk. Split them.
- **Missing boundaries** let scope grow during build. Write what is out.

## Not checked

Runtime behaviour under load, and anything outside the files, data or export the user gave.
